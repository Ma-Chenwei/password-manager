安全密码管理器技术设计手册

1. 项目概述

本项目是一款本地化密码管理器。

整体采用：

• 后端核心：Go 语言

• 客户端界面：Node.js + Electron，渲染层使用原生HTML/CSS/JS

• 加密核心：WASM 内存环境运行

• 数据保存方式：单一自包含 JSON 文件

• 不依赖：

◦ 浏览器 LocalStorage

◦ Cookie

◦ 云端数据库

◦ 系统明文密码存储

设计目标：

1. 用户密码数据完全由用户掌控

2. 密码库可以跨设备迁移

3. 不保存用户主密码

4. 所有敏感明文数据只存在于运行时内存

5. 使用标准密码学算法保护数据

6. 支持两套可切换UI主题：复古仿iOS3、液态玻璃仿iOS27

7. Electron 本地端口健康检测机制
2. 技术架构规定

2.1 后端开发语言

核心密码逻辑必须使用：
Go
负责：

• JSON 文件读写

• 密码库管理

• 加密流程控制

• 密钥刷新

• 数据校验

• 安全接口

• 本地TCP服务，监听 1107 端口（WASM加密核心通信服务）

推荐：

• Go 1.22+

• 标准 crypto 库

• WASM 编译支持
⚠️ 重要约束：所有加密、密钥派生、解密逻辑全部编译为 WASM，Electron 主进程/渲染进程不允许实现任何加密逻辑，只做UI与文件IO。
2.2 客户端开发

用户界面使用：
Node.js + Electron + 原生HTML/CSS/JS
负责：

• UI显示、两套主题切换渲染

• 用户输入

• 密码条目编辑

• 文件选择

• 导入导出操作

• 本地1107端口连通性检测

Electron 不允许：

• 保存主密码

• 保存密钥

• 保存解密后的密码数据

Electron 只能调用 Go/WASM 加密核心。
⚠️ 安全约束：Electron渲染进程禁止把解密后的明文密码存入localStorage、sessionStorage、进程缓存、日志；明文密码只能在WASM内存内，UI展示完成后立刻销毁。
2.2.1 本地1107端口检测机制

Go后端启动本地TCP服务，监听1107端口，监听地址支持外部配置，可选择绑定 127.0.0.1 或 0.0.0.0。

1. Electron主进程启动后，尝试建立TCP连接到配置的监听地址:1107

2. 检测逻辑：

◦ 端口连通成功：代表Go‑WASM加密服务就绪，渲染页面加载完成，允许用户进行解锁、密码操作

◦ 端口连接失败：展示错误提示，禁止所有加密相关操作；提示用户重启应用；不允许进入密码操作界面

3. 安全限制：

◦ 默认配置绑定127.0.0.1，仅允许本机回环地址访问，不对外网暴露；

◦ 当配置为0.0.0.0时，允许局域网其他设备连接，此时需要明确风险提示；

◦ 通信协议为本地二进制通信，不使用HTTP；不提供web访问能力

◦ 检测超时阈值：3000ms；连续3次检测失败弹出告警

4. 异常处理：

◦ 端口被占用：Go服务启动失败，Electron直接提示「加密核心启动异常，请关闭占用1107端口的程序后重试」

◦ 服务崩溃：Electron检测到连接断开，自动锁定全部UI，清空渲染层明文，提示重新初始化

2.2.2 前端双主题规范

渲染层基于HTML+CSS实现两套独立主题，主题切换完全在前端渲染层完成，不修改加密后端逻辑，不触碰密码数据。

主题切换约束

1. 主题切换仅修改前端CSS样式，不会触发任何加密、重写JSON文件操作。

2. 主题配置存储：主题选择状态存入Electron app.getPath('userData')普通配置文件，严禁存放任何密码、密钥、明文数据。

3. 渲染进程：两套主题使用同一套DOM结构，仅通过CSS类切换样式；不做两套独立DOM。

4. 安全强制：无论哪个主题，明文密码展示后必须及时销毁WASM内存，UI不缓存明文密码。

5. 主题切换时机：允许解锁前、解锁后任意切换；切换不会导致密码库重新加密。
前端技术栈：HTML + CSS变量 + Vanilla JS，不引入大型前端框架，保证Electron包体积小，减少攻击面。
3. 核心安全组件

系统必须使用以下密码学组件：
功能 算法 
密码派生 Argon2id 
数据加密 AES‑256‑GCM 
密钥组合 HKDF 
随机数生成 CSPRNG安全随机源 

✅ 实现备注：

• Argon2id：Go使用golang.org/x/crypto/argon2；参数需要固化：内存、迭代次数、并行度，不允许用户随意调小参数。

• AES‑256‑GCM：Nonce固定12字节（GCM标准推荐），禁止复用Nonce+密钥组合。

• HKDF：使用SHA‑256哈希，需要设置info上下文区分不同用途。

• 随机数：Go crypto/rand，禁止math/rand。
4. 密钥设计说明

系统存在两种核心秘密：

• S：系统密钥

• M：用户主密码

二者职责完全不同。
4.1 密钥 S（System Secret）

定义

S 是系统自动生成的随机密钥。

生成规则：
128位纯数字随机密钥
示例：
38492058392058392058392058392058
注意：

S：

• 用户不可见

• 用户不可设置

• 不直接输入

• 不进行持久化明文保存

用途：

作为密码库第二层安全因子。
🚨设计评审提醒：
原设计：S是128位纯数字字符串，这里存在隐患：
128位数字字符串，实际熵远低于128bit二进制随机数。
建议：改为128bit二进制随机字节，base64编码存储，不再限定纯数字；
如果坚持保留“数字字符串”，需要说明熵损失风险。
4.2 主密码 M（Master Password）

M 是用户自己设置的密码。

例如：
MyPassword@2026
特点：

• 用户记忆

• 用户输入

• 不保存

• 不上传

• 不写入文件

生命周期：
输入
 ↓
内存存在
 ↓
派生密钥
 ↓
使用完成
 ↓
销毁
内存销毁：WASM内存中，用完需要覆写内存（零填充），防止内存残留敏感数据。
4.3 S 与 M 的区别
项目 S M 
来源 系统生成 用户设置 
类型 随机数字密钥 用户密码 
是否保存 加密保存 永不保存 
是否可修改 可以刷新 用户修改 
是否输入 否 是 
作用 第二安全因子 第一认证因子 

简单理解：
M = 用户钥匙

S = 保险箱内部第二把钥匙
攻击者即使获得 JSON 文件：

必须同时破解：
M
+
S加密保护
安全说明：S被AES‑GCM加密存储；攻击者拿到JSON，只能暴力破解M，得到KeyA，再解密出S；之后再解密Vault。S本身不提供抵抗离线暴力破解的能力，只做多层防护。

12.1 使用标准密码学

系统采用：

• Argon2id

• AES‑256‑GCM

• HKDF

不依赖浏览器安全机制。

刷新密钥可以：

使旧版本泄露备份文件失效。

进行：

最终安全性取决于：
用户主密码强度

12.4 前端UI额外安全边界

2. 1107端口监听地址可外部配置；默认使用127.0.0.1仅本机访问；切换为0.0.0.0时，必须弹出风险警告，告知用户局域网设备可访问本服务。

3. 前端HTML渲染层永远拿不到解密后的原始密钥，全部加密运算在Go‑WASM侧完成。
13. 开发总结

本项目核心原则：
主密码 M 永不保存
系统密钥 S 永不明文保存
密码数据永远只保存密文
JSON 文件即可完成迁移
所有明文只存在运行时WASM内存
前端HTML实现两套可切换UI主题
本地1107端口作为加密核心通信通道，监听地址支持外部配置127.0.0.1或0.0.0.0
必须使用标准utf8格式
🔴额外工程安全约束（补充进文档）

1. WASM内存清理：M、S、明文密码使用完成，必须对内存做零字节覆写，禁止残留敏感数据。

2. AES‑GCM Nonce严禁复用：每次加密都生成全新12字节Nonce；Nonce与密文一起保存。

3. Argon2id参数固化：不要允许用户调低内存/迭代次数；防止弱派生。

4. 错误模糊化：解密失败不区分是密码错误、文件损坏、标签校验失败，统一提示，防止侧信道。

5. 文件写入安全：先在内存完成加密，校验解密可正常工作，再覆盖磁盘文件；禁止直接写损坏文件。

6. Electron沙箱：渲染进程禁止访问文件系统；文件读写通过主进程；加密逻辑全部交给WASM。

7. 版本标记：JSON增加version字段，方便后续格式升级兼容；旧版本文件拒绝加载。

8. 防内存dump风险：WASM环境无法完全防止内存dump；这是本地化密码管理器固有局限，需要在产品说明中告知用户。

9. 端口安全：Go服务监听地址由外部配置，默认绑定127.0.0.1；配置为0.0.0.0时必须展示风险提示；端口占用、服务崩溃时，Electron立刻锁定全部UI。

10. 主题安全：主题配置只保存UI偏好，绝不保存任何密码、密钥；主题切换不触发加密重算。

🟡待讨论的设计问题

1. S为“128位纯数字字符串”熵不足，建议改为二进制随机字节base64存储；

2. 主密码修改流程：当前文档没有写修改M的流程；修改M需要：解密全部数据，重新派生KeyA，重新加密S，更新JSON；

3. 密码库损坏恢复：JSON文件部分损坏如何处理；

4. 版本兼容：当算法/字段发生变更，如何处理旧的vault文件。

5. 1107端口冲突预案：备选端口策略。
